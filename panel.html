清理预览
帮助

配置与边界

  • 三层配置：工作区 config.yaml（只读基准）→ 面板覆盖 .uartix/yolo/config.json（只存差异）→ 每次实验的完整快照 train_runs/<实验>-<时间>.yaml。
  • 面板能点的，命令行也跑得起来：快照是公共语言；插件 runner 吃全部参数，你自己的 scripts/train.py 只认它的 20 个键。
  • 不改你的东西：config.yaml、scripts/*.py、00~07*.bat 全程只读。
  • 写只在这几处：.uartix/、annotations/、datasets/、runs/、logs/、models/、train_runs/。

模型、任务与数据

  • 只做 YOLO11 与 YOLO26：同一个 ultralytics 包里的两代模型，不是两套环境。
  • 老数据不用重标：YOLO 文本格式（images/ + labels/ + data.yaml）两代通用。
  • 权重与任务不搭会当场拦：拿 detect 权重跑 segment，开跑前就说明，不留下半份快照。
  • 模型库先按文件名推断：读一遍权重才知道它自带的任务、类别数和训练它的包版本；读不出就标出来，不猜。

参数与训练

  • 参数表不是抄的：每项来自当前 ultralytics 的 DEFAULT_CFG_DICT；包里没有就不出现。
  • 只存差异：面板只把与工作区 config.yaml 不同的键写进覆盖层，改回默认时 diff 自己消失。
  • 没有 half：8.4 已被 quantize 取代，那是导出页的事。
  • 续训只认 last.pt：best.pt 没有优化器状态。默认从 last.pt 开一个新 run（<原名>-resume），原 run 不动；Ultralytics 原生 resume 会写回原目录，只在高级选项里给。
  • 数字/文字任务：fliplr / flipud 保持 0；erasing 慎用。
  • 本机：16 GB 内存 → workers 8 左右；8 GB 显存 → batch 16，OOM 就减半。

训练快照与等价命令

每次开跑前写 train_runs/<实验名>-<时间>.yaml，含本次全部参数。训练由 runner/train_job.py 执行，跑完去 runs/<实验名>/args.yaml 对答案。快照能直接喂给你自己的 scripts/train.py --config …，只是它只认自己那 20 个键。

数据与标注

标注由你在 X-AnyLabeling 里完成。面板只认一个投料口 annotations/：一个子目录 = 一批素材，把导出目录整个丢进去即可。构建与体检都只读，不搬、不改、不删任何标注文件。

标注体检看什么

越界坐标、空标签、找不到图的标签、类别分布与 nc/names 是否一致、train 与 val 是否重名（数据泄漏）。它只报问题，修标注仍在 X-AnyLabeling 里做。

增强预览

显示的是引擎自己写出的 train_batch*.jpg，也就是上一次训练真实喂进网络的样本。面板不画假预览；改了增强参数要看新效果，跑一轮再回来。框上的数字是类别 id（从 0 开始），不是类别名。

曲线与 TensorBoard

曲线读的是引擎自己写的 runs/<实验>/results.csv；非续训重跑会删重建这个文件，所以“上一次的曲线”没了不是面板丢数据。想在 TensorBoard 里看：先 yolo settings tensorboard=True，再自己起 tensorboard --logdir runs（面板不替你装东西，也不替你起进程）。

部署与 Docker

部署工具不改你的 deploy_config*.ps1：面板在 .uartix/yolo/deploy/ 生成包装配置，覆盖 $Model / $ModelName / $CalibSources（校准图）。编译由工具自己的 deploy.ps1 调 Docker/Pulsar2 执行；Docker 引擎没起时先看「配置与边界」里的 WSL 修复步骤。

权限与批准

写权限只有那七枚目录，越界会被内核直接拒绝。0.5.2 起多了 联网（github.com / objects.githubusercontent.com / raw.githubusercontent.com），只用于下载官方权重；权限面变了，所以更新后要重新批准一次，批准卡上会多三行「联网 …」。宿主目前不按域名拦截，白名单由下载器自己做。安装、启用、发布这三件事始终由你点。

资产与清理

资产页是台账：数据集、训练产物、模型、部署包、回收站与磁盘占用。清理建议只是建议——每条都写着为什么、多大、被谁引用，默认一条都不勾。删除先进 .uartix/yolo/trash/，恢复回原路径，永久删除与清空要输入确认词；全部写 .uartix/yolo/audit.jsonl。原始 annotations/、用户脚本与外部部署目录永远不在清理范围；外部 work/calib 只统计体积并给一份手工清单。
